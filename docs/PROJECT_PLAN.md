# Pics2Text 项目开发计划书

## 1. 项目目标

建设一个可以接收大量用户照片、自动分析照片质量、将照片排版成指定文字，并输出适用于大型载体印刷文件的平台。

首个正式业务场景以“中国人能飞”照片文字和火箭表面展示为目标，但领域模型应支持后续扩展到建筑外墙、展板、车身等其他载体。

## 2. 正式版本范围

正式版本包含：

- 用户登录、角色权限和项目级数据权限；
- 项目、成员、照片授权和审核管理；
- 浏览器直传对象存储、分片上传和断点续传；
- 图片格式、清晰度、颜色、人脸、重复照片分析；
- 文字蒙版、网格生成、照片评分和自动分配；
- 布局版本、人工换图、裁切调整和历史版本；
- 火箭表面展开、禁印区域和三维预览数据；
- 低清预览、超大图分块渲染和印刷文件交付；
- 异步任务、失败重试、任务恢复和进度通知；
- 日志、指标、链路追踪、审计、备份和部署能力。

正式版本暂不包含：

- 面向公众的开放素材交易市场；
- 自研人脸识别模型；
- GPU 作为运行必需条件；
- 一开始就拆分大量业务微服务；
- 对所有 CAD 格式的通用解析。

## 3. 架构原则

采用“轻量 DDD + 六边形架构 + 模块化单体 + 独立异步 Worker”。

运行时包含三个可独立部署的应用：

```text
mosaic-api
    普通 HTTP API、认证、业务事务、任务创建、SSE 进度

mosaic-analysis-worker
    照片分析、文字蒙版、照片分配、布局优化

mosaic-render-worker
    缩放、裁切、拼接、分块渲染、印刷文件输出
```

代码使用一个 Maven 多模块仓库。领域模块之间通过公开应用接口和领域事件协作，不允许跨模块直接调用 Mapper。

```text
mosaic-platform/
├── mosaic-shared-kernel/
├── mosaic-identity/
├── mosaic-project/
├── mosaic-photoasset/
├── mosaic-layout/
├── mosaic-surface/
├── mosaic-rendering/
├── mosaic-api/
├── mosaic-analysis-worker/
└── mosaic-render-worker/
```

## 4. 技术栈基线

| 范围 | 选型 |
|---|---|
| Java | Java 21 LTS，Eclipse Temurin |
| 服务框架 | Spring Boot 4.1.x、Spring MVC、Jakarta Validation |
| 认证鉴权 | Sa-Token Spring Boot 4 Starter、Sa-Token Redis |
| 持久化 | MyBatis-Plus Spring Boot 4 Starter、Mapper XML |
| 数据库 | PostgreSQL、Flyway、HikariCP |
| 缓存 | Redis |
| 消息队列 | RabbitMQ Quorum Queue |
| 文件存储 | S3 兼容对象存储，开发环境使用 SeaweedFS |
| 图片分析 | OpenCV、Java2D，必要时引入 ONNX Runtime |
| 图片渲染 | libvips、LittleCMS/ICC |
| 前端 | React、TypeScript、Vite、Ant Design |
| 画布 | PixiJS |
| 三维预览 | Three.js |
| 前端状态 | TanStack Query、Zustand |
| 数据库测试 | Testcontainers PostgreSQL |
| 测试 | JUnit 5、AssertJ、Mockito、ArchUnit、Playwright |
| 可观测性 | Actuator、Micrometer、OpenTelemetry、Prometheus、Grafana、Loki、Tempo |
| 交付 | Docker、Docker Compose；生产编排按部署环境决定 |

依赖的精确版本必须集中定义在父 `pom.xml`，不得由子模块各自声明版本。升级依赖时需要记录兼容性验证结果。

## 5. 持久化约束

- 领域对象不得使用 `@TableName`、`@TableId` 等持久化注解；
- MyBatis-Plus 的 Record/DO 仅存在于 `infrastructure.persistence`；
- 领域层定义 Repository 接口，基础设施层负责实现；
- 简单 CRUD 使用 `BaseMapper` 和 Lambda Wrapper；
- 复杂联表、任务抢占、JSONB 和数据库特性使用 Mapper XML；
- 数万条以上的位置数据优先使用批处理，达到十万级时评估 pgJDBC `COPY`；
- 数据库结构由 Flyway 管理，禁止依赖运行时自动建表；
- JSONB 仅保存结构可能变化且不经常作为条件查询的数据；
- 时间字段统一使用 PostgreSQL `timestamptz`；
- 布局等可并发修改的聚合必须使用版本号乐观锁。

## 6. 安全基线

- 浏览器用户访问 API 使用 Sa-Token；
- 多实例会话统一存储在 Redis；
- 密码使用 Argon2id 或 BCrypt，不保存明文；
- 功能权限使用权限码，资源访问还必须进行项目级数据权限检查；
- 原图保持私有，只通过短时预签名地址访问；
- 上传完成后校验文件魔数、格式、大小和真实分辨率；
- 清理 GPS 等敏感 EXIF 信息；
- Worker 使用独立数据库、RabbitMQ、对象存储凭证；
- 日志中禁止出现密码、Token、预签名 URL 和照片二进制内容；
- 关键操作写入审计日志。

## 7. 阶段完成与文档规则

每个开发阶段只有同时满足以下条件才可以标记为完成：

1. 计划范围内的代码已经实现；
2. 自动化测试通过；
3. 阶段验收项通过；
4. 数据库变更已加入 Flyway；
5. 配置和部署变更已记录；
6. 已在 `docs/progress/` 下创建对应的阶段完成文档；
7. 已更新 `docs/progress/README.md` 的状态和文档链接。

阶段完成文档必须基于 [阶段完成文档模板](templates/PHASE_COMPLETION_TEMPLATE.md)，至少说明：

- 本阶段完成了什么；
- 主要架构和设计决定；
- 新增或修改的 API、表、事件和配置；
- 测试方法与结果；
- 运行和验证方式；
- 已知限制和遗留事项；
- 下一阶段的依赖与注意事项。

禁止只写“已完成”。文档必须让没有参与开发的人可以理解、运行并验证本阶段结果。

## 8. 开发阶段

### P00：工程骨架与质量基线

目标：建立可编译、可测试、可本地启动的工程基础。

需要完成：

- 创建 Maven 多模块结构；
- 固定 Java 21 和依赖版本管理；
- 建立领域层、应用层、基础设施层和接口层约束；
- 创建 API、Analysis Worker、Render Worker 三个启动模块；
- 接入统一异常、错误码、请求 ID 和结构化日志；
- 配置代码格式、静态检查和 ArchUnit 架构测试；
- 创建 PostgreSQL、Redis、RabbitMQ、SeaweedFS 的本地 Docker Compose；
- 接入 Flyway 和第一份数据库迁移；
- 建立单元测试、集成测试和 CI 命令；
- 编写本地开发环境启动说明。

验收标准：

- 一条命令可以启动全部本地依赖；
- 三个Java应用可以启动并通过健康检查；
- 架构测试能阻止领域层依赖基础设施层；
- 空数据库可以完整执行Flyway迁移；
- CI可以完成编译和测试。

完成文档：`docs/progress/P00-engineering-foundation.md`

### P01：身份认证与项目权限

目标：完成用户登录和项目级授权基础。

需要完成：

- 用户、角色、权限、项目成员模型；
- Sa-Token登录、登出、续期和踢出；
- Redis会话存储；
- Argon2id或BCrypt密码校验；
- 功能权限码和项目级数据权限；
- 管理员、项目管理员、审核员、设计师和只读用户角色；
- 登录失败限制、审计日志和敏感字段脱敏；
- 用户与项目成员管理API。

验收标准：

- 多实例API能够共享登录状态；
- 无权限用户无法访问其他项目资源；
- 退出或踢出后Token立即失效；
- 认证和越权场景有自动化测试。

完成文档：`docs/progress/P01-identity-and-access.md`

### P02：项目与照片上传

目标：完成项目创建、照片直传和资产入库。

需要完成：

- 项目生命周期和基础配置；
- 照片元数据、授权状态和审核状态；
- S3兼容对象存储预签名上传；
- 分片上传、完成确认和失败清理；
- 文件格式、魔数、大小和分辨率校验；
- SHA-256完全重复检测；
- 原图、缩略图、预览图对象Key规范；
- 照片删除、撤回和保留策略；
- 上传进度及失败原因展示接口。

验收标准：

- 大文件不经过API进程转发；
- 未完成和伪造上传不能进入可用资产；
- 相同文件能被识别；
- 无权限用户无法获得对象访问地址。

完成文档：`docs/progress/P02-project-and-upload.md`

### P03：异步任务与可靠消息

目标：建立照片分析、排版和渲染共用的可靠任务基础设施。

需要完成：

- `processing_job`统一任务模型和状态机；
- RabbitMQ交换机、Quorum Queue、重试队列和死信队列；
- Publisher Confirm和消费者手动ACK；
- Transactional Outbox；
- 消费幂等表或幂等键；
- 任务心跳、超时检测和僵尸任务恢复；
- 有限重试、指数退避和人工重新执行；
- SSE任务进度推送；
- 任务取消语义和不可取消阶段定义。

验收标准：

- 数据库提交后消息不会静默丢失；
- 同一消息重复投递不会重复生成业务结果；
- Worker进程中断后任务可以恢复；
- 超过最大重试次数的任务进入死信队列。

完成文档：`docs/progress/P03-job-and-messaging.md`

### P04：照片分析与审核

目标：产生排版所需的照片质量和视觉特征。

需要完成：

- 原图解码安全限制；
- EXIF方向处理和敏感EXIF清理；
- 多级缩略图；
- 拉普拉斯方差清晰度检测；
- 平均亮度、对比度和Lab主色特征；
- dHash/pHash感知查重；
- 人脸或主体检测；
- 推荐裁切框；
- 自动审核规则和人工复核接口；
- 固定算法样本集和回归指标。

验收标准：

- 损坏图片和超大图片不会拖垮Worker；
- 相同或压缩后的重复照片可以形成重复组；
- 裁切建议不会明显截断主要人脸；
- 算法变更可通过固定样本集比较。

完成文档：`docs/progress/P04-photo-analysis.md`

### P05：文字蒙版与网格生成

目标：将指定文字转换为稳定、可排版的照片位置集合。

需要完成：

- 字体资产打包和字体许可记录；
- 文字横排、竖排、字号、字重和间距配置；
- 灰度文字蒙版生成；
- 网格、覆盖率和边缘处理算法；
- 笔画过细检查和可读性警告；
- 规则网格和错位网格策略；
- 文字蒙版及网格的可视化调试输出；
- 参数配置持久化。

验收标准：

- 相同字体和参数产生可重复结果；
- 网格不会大面积溢出文字边界；
- 缩小预览仍能识别目标文字；
- 字体缺失时给出明确失败信息。

完成文档：`docs/progress/P05-text-mask-and-grid.md`

### P06：照片评分、分配与布局优化

目标：自动生成可用的照片文字布局。

需要完成：

- 照片候选筛选；
- 亮度、颜色、裁切损失、重复和相邻相似度评分；
- 评分权重配置和版本化；
- 贪心分配策略；
- 分区候选集，避免完整巨型成本矩阵；
- 模拟退火或局部交换优化；
- 固定随机种子和结果复现；
- 布局质量指标；
- 性能基准和内存限制。

验收标准：

- 指定照片集合和随机种子可以复现布局；
- 每个位置最多一张照片；
- 不允许重复的照片不会被重复使用；
- 达到目标规模时，耗时和内存满足既定基准。

完成文档：`docs/progress/P06-layout-algorithm.md`

### P07：布局版本与人工编辑

目标：允许设计人员安全地人工调整自动布局。

需要完成：

- Layout与不可变LayoutVersion；
- 交换照片、替换照片和裁切调整；
- 操作命令和操作历史；
- 乐观锁和并发编辑冲突；
- 自动保存和恢复；
- 布局锁定、解锁及发布流程；
- PixiJS可视区域渲染；
- 缩放、平移、搜索照片和位置定位；
- 低清预览生成。

验收标准：

- 任意人工修改可以追溯到用户和时间；
- 两个用户同时编辑不会静默覆盖；
- 锁定版本不能继续修改；
- 数万位置画布仍可交互操作。

完成文档：`docs/progress/P07-layout-editor.md`

### P08：载体表面与三维预览

目标：把二维布局准确映射到火箭或其他曲面载体。

需要完成：

- SurfaceTemplate领域模型；
- 真实尺寸、比例和单位体系；
- 圆柱展开坐标转换；
- 接缝、安全边距和禁印区域；
- 舱段和关键结构标记；
- 二维布局合法性校验；
- Three.js圆柱或模型纹理预览；
- UV映射数据输入接口；
- 预览精度与印刷坐标一致性测试。

验收标准：

- 二维坐标可以稳定映射到三维预览；
- 禁印区域和接缝冲突能在发布前被阻止；
- 坐标单位和缩放关系有自动化测试；
- 同一版本预览与最终渲染使用同一坐标源。

完成文档：`docs/progress/P08-surface-and-3d-preview.md`

### P09：高清渲染与印刷交付

目标：稳定生成超大尺寸印刷文件。

需要完成：

- RenderJob及不可变输入清单；
- 分块渲染和位置空间索引；
- 按需读取原图、裁切、缩放和合成；
- libvips适配层和原生内存保护；
- TIFF/BigTIFF或印厂指定格式；
- DPI、出血、裁切线和定位点；
- ICC色彩配置和颜色转换；
- 成品SHA-256、Manifest和照片位置清单；
- 临时文件清理和失败恢复；
- 成品审批和受控下载。

验收标准：

- 渲染过程不需要把整张成品图放入JVM堆；
- Worker崩溃不会产生被误认为成功的文件；
- 成品能够通过校验和验证；
- 使用真实目标尺寸完成一次端到端试渲染。

完成文档：`docs/progress/P09-render-and-print.md`

```text
P07 人工编辑 ──┐
P08 载体预览 ──┴── P09 高清渲染

P01～P09 ── P10 完整前端 ── P11 生产治理 ── P12 上线交付
```

P05可在P04开发期间并行进行。P08可以在P07后半段并行。P11的基础埋点应从P00开始，P11阶段负责补齐和正式验收，而不是最后才开始接入。

## 10. 里程碑

| 里程碑 | 包含阶段 | 可验证结果 |
|---|---|---|
| M1 工程可运行 | P00～P03 | 可以登录、上传照片并可靠创建异步任务 |
| M2 自动排版可用 | P04～P06 | 可以从照片自动生成文字布局和预览 |
| M3 设计工作流可用 | P07～P08 | 可以人工调整并查看曲面三维效果 |
| M4 印刷闭环 | P09～P10 | 可以从运营后台生成并下载印刷文件 |
| M5 生产上线 | P11～P12 | 通过安全、容量、恢复和上线验收 |

具体日期需要结合团队人数、目标照片规模、火箭表面数据和印厂要求估算，本计划不在需求未确定时虚构工期。

## 11. 开发任务的完成定义

每个功能任务的 Definition of Done：

- 代码已实现并经过审查；
- 单元或集成测试覆盖核心路径和失败路径；
- 不绕过模块边界访问其他模块的数据层；
- API已更新OpenAPI说明；
- 数据库变更具有正向Flyway脚本；
- 新增配置具有默认值、说明和环境变量名称；
- 日志不包含敏感信息；
- 相关指标和错误码已补充；
- 阶段文档同步更新；
- 本地或测试环境完成可复现验证。

## 12. 需要尽早确认的外部输入

- 首次项目预计照片数量及单张文件大小；
- 目标印刷尺寸、DPI、文件格式和色彩空间；
- 火箭表面真实尺寸、接缝和禁印区域；
- 是否提供CAD或UV展开数据；
- 照片授权、撤回和使用期限规则；
- 是否需要匿名投稿、短信登录或第三方登录；
- 项目成员角色和审核流程；
- 部署环境、对象存储及数据库形态；
- 可接受的排版耗时和最终渲染耗时。

这些信息不会阻塞P00工程搭建，但必须在对应业务阶段开始前确认并记录到阶段文档。
